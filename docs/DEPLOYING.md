# Deploying

The app is a plain Node process and a Postgres database. No build step, no bundler,
no framework — `node src/server.js` with a `DATABASE_URL` is the whole of it. That
makes almost any host workable; what follows is what it needs, not where to put it.

## What it needs

| | |
|---|---|
| Node | ≥ 22 (`engines` in package.json; developed on 24) |
| Postgres | any recent version; one small database |
| Memory | small — the simulation is arithmetic, and the heaviest query reads one camp |
| Process count | **one**, until the note on scaling below is dealt with |

## Environment

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes | `postgres://user:pass@host:5432/wasteland` |
| `NODE_ENV` | yes, in production | Anything but `production` leaves session cookies without the `Secure` flag |
| `PORT` | no | Defaults to 3000 |
| `TRUST_PROXY` | behind a proxy | Number of proxies in front of the app — `1` for a single reverse proxy. **Leave unset when the process is reachable directly** |

`TRUST_PROXY` deserves the emphasis. Express takes the caller's address from
`X-Forwarded-For` when it is set, and that header is caller-supplied: trusting it
when nothing upstream overwrites it lets anyone claim any address and walk through
the rate limiter unchallenged. Set it to the real number of proxies, or not at all.

## First run

```
npm ci --omit=dev
npm run migrate     # idempotent; applies anything unapplied, in order
npm run seed        # content: items, regions, recipes. Idempotent — upserts by slug
node src/server.js
```

Migrations and the seed are safe to run on every deploy. Migrations are recorded in
`schema_migrations` and skipped once applied; the seed upserts on natural keys, which
is also how balance changes to regions and recipes reach a running game.

Note the npm scripts (`npm start`, `npm run migrate`) wrap commands in
`scripts/with-db.mjs`, which brings up a **local WSL Docker container** — that is a
development convenience and is wrong on a server. Call `node` directly, as above.

## Behind a reverse proxy

Terminate TLS at the proxy, forward to `PORT`, and set `TRUST_PROXY=1`. Session
cookies are `HttpOnly`, `SameSite=Strict` and `Secure` in production, so **the app
must be served over HTTPS** or nobody will stay logged in.

`SameSite=Strict` is doing real work here: it is what stands in for CSRF tokens, since
a cross-site form post arrives without the cookie. Do not relax it without replacing
it with something.

## Backups

`pg_dump` on a schedule. There is no other state — no uploads, no cache, no files.
Everything a player has ever done is in Postgres, and the game has no undo.

## Scaling, and the one thing that would break

Run **one instance** for now. Two would be wrong in exactly one place, and it is
written down rather than left to be discovered:

- **The rate limiter is in memory** (`src/web/rate-limit.js`). Two instances means two
  counters and twice the allowance. The fix is noted in that file: move the counter
  into Postgres beside `sessions`, keeping the same shape.

Everything else is already safe for concurrency, and deliberately so:

- The tick takes `select … for update` on the settlement row before reading, so two
  simultaneous requests cannot both apply the same elapsed hours.
- World events are generated by whoever needs them, with the primary key deciding who
  wins the insert and `on conflict do nothing` making the loser correct.
- Every queue-of-one is a partial unique index in the database, not a check in code.

## Health

There is no `/health` endpoint yet — add one before putting this behind anything that
expects to poll for readiness. `GET /` is a cheap public page that touches the
database only for the session lookup, so it is a reasonable stand-in meanwhile.

## Something to know about the clock

The game's whole premise is resolving elapsed time on page load, so **the server's
clock matters**. A large jump backwards is handled (the tick refuses to run
backwards), but a jump forwards silently simulates that time. Keep NTP running, and
avoid restoring a database backup into a much later clock without expecting the first
page load to resolve everything in between.
